# Intune Docs Studio 0.1.3

[English](#english) | [Nederlands](#nederlands)

## English

Reviewed notes for the owner-authorized stable promotion. Publication is
confirmed only by the actual GitHub Release, verified assets and workflow.

## Since the previous stable version (v0.1.2)

This patch repairs post-publication release-note verification. There are no
application feature or configuration changes. The first published stable
release is [v0.1.2](https://github.com/helmerzNL/intune-docs-studio/releases/tag/v0.1.2);
its full cumulative English and Dutch notes remain in
[`v0.1.2.md`](v0.1.2.md). That release, tag and its assets are unchanged.

## Good to know when updating

No new operator behavior, data format or setting is introduced. Users already
running v0.1.2 have the same application functionality. Use the latest verified
stable package for the new version/build identity; do not copy credentials or
active browser profiles between installations.

## Changes and user-visible effects

- Fixed a false post-publication failure when GitHub returns release notes with
  CRLF rather than LF line endings or surrounding whitespace/a final newline.
  Verification compares normalized text on both sides while still rejecting
  substantive changes to the reviewed notes.
- Retained immutable tag, asset digest, manifest, exact-commit, promotion and
  latest/non-prerelease checks. The workflow never rewrites an existing release
  or rebuilds an already recorded artifact to satisfy verification.
- Added regression coverage for LF/CRLF publication and recovery, preserving
  release text and package bytes, and rejecting unreviewed content changes.
  A successful verification allows the normal validated main-to-beta back-merge.

## Update instructions

Download `IntuneDocsStudio.zip` and `release-manifest.json` from the stable GitHub
Release. Compare the ZIP SHA-256 with the manifest, and verify version `0.1.3`,
channel `stable` and source commit. Stop the app before replacing files.
Follow [`QUICKSTART.md`](../../QUICKSTART.md) and
[`docs/operations.md`](../operations.md), then start `Start-IntuneDocs.cmd`
and verify `/api/health` and `/api/version`. Keep the prior ZIP until the new
package starts correctly.

Preserve generated documentation, offline policy sets, imported packs, reports
and documentation Git history outside the installation. Do not back up or
restore tokens or active browser sessions; sign in again when needed.

## Dependencies and runtime

No change: Windows with PowerShell 7 or later (`pwsh`) is required. No runtime
package dependency or automatic PowerShell installation/update is added.
Git and `Microsoft.Graph.Authentication` remain optional for their respective
publishing/sign-in methods. Localhost binding, policy import limits and browser
connection timeouts are unchanged from v0.1.2.

## Data implications

No migration or customer-data processing change. Assessment remains read-only;
output, imported packs and reports remain customer-owned local data. Browser
profiles remain sensitive authentication material, not backup data. No new
upload, token export or credential storage is introduced.

## Unverified integrations

This repair was reproduced with synthetic LF/CRLF release responses; it does not
add real-tenant, licensed CIS build-kit, managed-browser, Conditional Access or
external Git-provider compatibility claims. Portal-token reuse remains an
unsupported Microsoft integration pattern. The v0.1.2 release was independently
verified with matching tag, manifest/ZIP digests and complete bilingual text;
its original workflow failed only after publication on the text representation.
That historical failed run remains unchanged. This patch's publication and
validated back-merge still require verification after its promotion.

## Nederlands

Beoordeelde notes voor de door de eigenaar geautoriseerde stabiele promotie.
Publicatie wordt pas bevestigd door de echte GitHub Release, geverifieerde
bestanden en workflow.

## Sinds de vorige stabiele versie (v0.1.2)

Deze patch herstelt verificatie van release notes na publicatie. Er zijn geen
applicatiefuncties of configuraties gewijzigd. De eerste gepubliceerde stabiele
release is [v0.1.2](https://github.com/helmerzNL/intune-docs-studio/releases/tag/v0.1.2);
de volledige cumulatieve Engelse en Nederlandse notes staan nog in
[`v0.1.2.md`](v0.1.2.md). Die release, tag en bestanden blijven ongewijzigd.

## Goed om te weten bij het bijwerken

Er zijn geen nieuwe beheerhandelingen, gegevensformaten of instellingen.
Gebruikers van v0.1.2 hebben dezelfde applicatiefuncties. Gebruik het nieuwste
geverifieerde stabiele pakket voor de nieuwe versie-/buildidentiteit; kopieer
geen referenties of actieve browserprofielen tussen installaties.

## Wijzigingen en zichtbare gevolgen

- Een onterechte fout na publicatie is opgelost wanneer GitHub release notes
  met CRLF in plaats van LF, omringende witruimte of een afsluitende newline
  terugstuurt. Verificatie vergelijkt aan beide kanten genormaliseerde tekst
  en blijft inhoudelijke wijzigingen in de beoordeelde notes weigeren.
- Onveranderlijke tags, bestandsdigests, manifest-, exacte commit-, promotie-
  en latest/niet-prereleasecontroles blijven behouden. De workflow herschrijft
  nooit een bestaande release en bouwt een geregistreerd artifact niet opnieuw
  om verificatie te laten slagen.
- Regressietests zijn toegevoegd voor LF-/CRLF-publicatie en herstel, met behoud
  van releasetekst en pakketbytes en afwijzing van niet-beoordeelde inhoud.
  Geslaagde verificatie laat de normale gevalideerde main-naar-beta-terugmerge toe.

## Update-instructies

Download `IntuneDocsStudio.zip` en `release-manifest.json` uit de stabiele
GitHub Release. Vergelijk ZIP-SHA-256 met het manifest en controleer versie
`0.1.3`, kanaal `stable` en broncommit. Stop de app voordat u bestanden vervangt.
Volg [`QUICKSTART.md`](../../QUICKSTART.md) en
[`docs/operations.md`](../operations.md), start daarna `Start-IntuneDocs.cmd`
en controleer `/api/health` en `/api/version`. Bewaar de vorige ZIP totdat
het nieuwe pakket correct start.

Bewaar gegenereerde documentatie, offline beleidssets, geimporteerde packs,
rapporten en documentatie-Git-geschiedenis buiten de installatie. Maak geen
back-up van tokens of actieve browsersessies en herstel die niet; meld zo nodig
opnieuw aan.

## Afhankelijkheden en runtime

Geen wijziging: Windows met PowerShell 7 of hoger (`pwsh`) blijft vereist.
Er zijn geen runtimepakketafhankelijkheden of automatische PowerShell-
installaties/updates toegevoegd. Git en `Microsoft.Graph.Authentication`
blijven optioneel voor hun publicatie-/aanmeldmethoden. Localhostbinding,
beleidsimportlimieten en browserverbindingstime-outs blijven gelijk aan v0.1.2.

## Gevolgen voor gegevens

Geen migratie of wijziging in verwerking van klantgegevens. Assessment blijft
alleen-lezen; uitvoer, geimporteerde packs en rapporten blijven lokale
klantgegevens. Browserprofielen blijven gevoelig authenticatiemateriaal,
geen back-upgegevens. Er is geen nieuwe upload, tokenexport of opslag van
referenties toegevoegd.

## Niet-geverifieerde integraties

Deze reparatie is gereproduceerd met synthetische LF-/CRLF-releaseresponses;
er worden geen nieuwe compatibiliteitsclaims gedaan voor echte tenants,
gelicentieerde CIS build-kits, beheerde browsers, Conditional Access of externe
Git-providers. Hergebruik van portaltokens blijft een niet door Microsoft
ondersteund integratiepatroon. De v0.1.2-release is onafhankelijk geverifieerd
met overeenkomende tag, manifest-/ZIP-digests en volledige tweetalige tekst;
de oorspronkelijke workflow faalde pas na publicatie op de tekstrepresentatie.
Die historische mislukte run blijft ongewijzigd. Publicatie en gevalideerde
terugmerge van deze patch vereisen nog verificatie na de promotie.
