# Intune Docs Studio 0.1.1

## English

Planned release notes for the owner-requested promotion of `beta` to `main`.
This document does not mean that a stable package has been published.

## First stable release

No previous published stable release or version tag was present when these
notes were prepared. The initial `main` baseline records version `0.1.0`;
the default patch increment selects `0.1.1`. These notes cover the cumulative
changes since that initial baseline, not just the latest beta change.
The stable pipeline owns the version increment; this preparation does not
change `VERSION`.

## Good to know when updating

- Policy collection in the dashboard now requires an explicit **Load policies**
  choice after sign-in. **Not now** opens Home without collecting; documentation
  and assessment remain disabled until a policy source is loaded or imported.
  Loading live policies validates the Graph sign-in and requests reauthentication
  if it is no longer usable.
- The dashboard and new reports support ten languages. A supported browser
  language is used on the first visit, otherwise English; a saved browser choice
  takes precedence. Jobs retain the language selected when they start. Existing
  reports are not rewritten when the interface language changes.
- Portal-session sign-in offers **Automatic**, **Microsoft Edge** and
  **Google Chrome**. Automatic prefers Edge and uses Chrome only if Edge is absent;
  policy or connection failures never switch browsers. Edge retains its existing
  app profile; Chrome uses a separate one. **Forget saved sessions** clears both.
- Managed browsers can block portal-session sign-in before a window opens.
  Review the named policy with IT rather than disabling protection. A managed
  `UserDataDir` also blocks launch because it overrides the isolated app profile.
  Use an approved management workstation or standard Graph sign-in with admin
  consent if CDP is prohibited.
- Keep imported assessment packs and reports separate from the application and
  documentation output. Offline documentation supports only five policy families;
  it does not turn an offline policy export into a complete tenant backup.
- Only five checks across four partial Microsoft packs are bundled. Coverage
  and configuration alignment are not device compliance, certification or a
  complete benchmark assessment. Review applicability, assignments and collection
  limitations before using results.

## Changes and user-visible effects

- Added a guided, six-step assessment workflow for choosing platforms, importing packs and
  baselines, supplying comparison context, reviewing the scope, and inspecting
  results.
- Added policy-alignment assessment across Windows 11, macOS, iOS/iPadOS, and
  Android Enterprise. Results include evidence, limitations, and local
  Markdown/JSON reports. This measures configuration alignment, not device
  compliance or certification; bundled Microsoft inventories remain partial.
- Added import of customer-supplied schema-1 rule packs and supported CIS
  Intune build-kit ZIP archives. Supported Settings Catalog policies are
  converted to local packs; the app does not download, retain, or authenticate
  the source ZIP.
- Added a sign-in landing page and separate policy-documentation and
  assessment workspaces, with Home showing the current policy source.
- Policies load only after explicit post-sign-in consent into one tenant-scoped, in-memory
  snapshot reused by documentation and assessment. Home shows loading progress,
  family counts and collection time, with retry/refresh controls. Partial loads
  retain collection limitations; documentation skips incomplete policy families
  and preserves previous files without pruning. Other selected documentation
  areas are still collected on export. Command-line exports continue to collect
  directly; optional Git publishing remains separate from assessment.
- Added offline JSON-folder/ZIP policy-set import/export with versioned hashes,
  transactional source replacement and conservative legacy `_raw` support.
  Documentation and Assessment work without Microsoft sign-in or Graph requests.
  Offline documentation is restricted to the five policy families; unavailable
  evidence remains unknown and incomplete-family output is preserved.
- Added a multi-item import queue and structured added/skipped/failed summary,
  custom reference-policy conversion, clearer pack/profile/context/review displays,
  confirmed imported-library removal and a native Windows host-folder picker.
  Unsupported, incomplete, conflicting or secret reference mappings are skipped,
  never evaluated as generic JSON equality or labeled CIS/certified.
- Assessment policy tables reuse the documentation writer's setting labels and
  value formatting in the dashboard and Markdown/JSON reports. Exact typed
  comparison evidence remains available; incomplete, secret or unsupported
  evidence is explicitly withheld from readable tables, not interpreted as empty.
- Improved large policy imports, structured import/report errors, Windows build
  and platform applicability, and assessment date formatting. Unknown,
  unsupported or incomplete evidence remains **not assessed**, not a pass.
  Unassigned policies do not demonstrate deployment, and potential conflicts
  do not prove overlapping effective targeting.
- Added Danish, German, English, Spanish, French, Italian, Dutch, Norwegian
  Bokmal, European Portuguese and Swedish for the interface and newly started
  documentation/assessment jobs, with a keyboard-accessible selector ordered by
  native language name. Translations and flags ship locally; no translation
  service or CDN is contacted. Technical identifiers, typed policy values,
  customer names, provider setting labels and external benchmark wording are
  not translated. CLI exports default to `en-GB`; `-Locale` selects another language.
- Added portal browser selection in the dashboard and `-PortalBrowser
  auto|edge|chrome` for command-line portal capture. Local mandatory machine/user
  policy diagnostics cover `RemoteDebuggingAllowed`,
  `DeveloperToolsAvailability`, private-browsing restrictions when forcing the
  account picker, and `UserDataDir`. The app checks CDP HTTP readiness and
  WebSocket connectivity and reports startup or connection failures explicitly.
  It does not change enterprise policy, copy everyday browser profiles or
  automatically try another browser after a failure.
- Added a Dutch README and aligned it with the English instructions, including
  five existing Dutch-interface screenshots using synthetic demonstration data.
- Added structured issue templates, an extended contributor PR checklist and
  owner-reviewed release-note requirements for stable promotions.

## Update instructions

After the owner merges the promotion and the stable workflow succeeds,
download the verified `IntuneDocsStudio.zip` and `release-manifest.json` from
the GitHub Release. Check the ZIP SHA-256 against the manifest and verify the
version, channel and source-commit identity.

Stop the running application before replacing application files. Extract the
ZIP into the intended application folder as described in
[`QUICKSTART.md`](../../QUICKSTART.md) and
[`docs/operations.md`](../operations.md). Start with `Start-IntuneDocs.cmd`;
verify `/api/health` and `/api/version`, including the expected `stable`
channel, version and commit. A stable-channel package omits the beta title
marker. Keep the previous ZIP until the update is confirmed.

Preserve generated documentation, offline policy sets, imported assessment
packs, reports and documentation Git history separately from the installation.
Re-check the active policy source, language, report/output paths, approved
portal browser and chosen tenant before generating new output. Do not back up,
copy or restore tokens or active browser-session profiles; sign in again if needed.

## Dependencies and runtime

The supported runtime remains Windows with PowerShell 7 or later (`pwsh`).
The application adds no runtime package dependencies and does not install or
update PowerShell automatically. Git remains optional for documentation
commit/push, and `Microsoft.Graph.Authentication` remains optional for the
Graph PowerShell sign-in method. The app still binds to localhost only.

New import limits are explicit: policy-set inputs allow a 32 MiB ZIP,
1,000 entries, 500 JSON files, 10 MiB per JSON, 64 MiB total JSON,
64 JSON levels and 16 folder levels. A CIS build-kit ZIP is limited to
32 MiB; a schema-1 rule-pack JSON file is limited to 10 MiB. An assessment
selects 1-64 exact rule-pack versions/profiles. Consult the
[import reference](../assessment-rule-packs.md) for the additional archive,
conversion and rule-schema bounds. Portal CDP startup retains a 40-second
readiness window and uses a five-second WebSocket connection probe.

## Data implications

Assessment is read-only against the tenant. A customer-supplied build-kit ZIP
is processed in memory and is not retained; only validated generated rule
packs are stored in the local imported-pack directory. Assessment reports are
written only to the operator-selected local report directory. No customer
configuration, archive, or report is automatically uploaded, committed, or
pushed. Imported packs, licensed CIS downloads, and reports remain
customer-owned data subject to applicable access controls and licensing.

Versioned offline policy sets include hashes and supported policy/reference
evidence, excluding authentication objects and recognized secrets. Remaining
configuration is sensitive. Incomplete collections never justify pruning
existing documentation. Imported policy sources remain independent of sign-in
and are never silently replaced by live tenant data.

The portal browser may persist authentication material under
`%LOCALAPPDATA%\IntuneDocsStudio\browser-profile` (Edge) or
`%LOCALAPPDATA%\IntuneDocsStudio\browser-profile-chrome` (Chrome). Treat both
as sensitive, not application backup data. App-managed access tokens remain
in process memory; this release does not add token-file export.

## Unverified integrations

No licensed CIS build-kit archive or live customer tenant was available for
validation. The exact archive layout and conversion coverage therefore remain
unverified; inspect the import summary and resulting rules before assessment.
Converted CIS labels do not authenticate the source or establish complete
benchmark coverage, CIS conformance, certification, or device compliance.
Assessment evidence is limited to the collected configuration and supported
rules.

Portal-token reuse remains an unsupported Microsoft integration pattern.
Synthetic tests do not establish compatibility with every managed Edge/Chrome
configuration, cloud browser policy, endpoint protection product, Conditional
Access policy, sign-in flow or current portal implementation. Local registry
checks do not prove effective permission to debug a browser. Real-tenant
Graph permissions, effective assignment, Azure DevOps/Git credentials and
customer-specific update/restore procedures require operator verification.

The stable publication transaction has not been exercised for this proposed
first release. The presence and permissions of `IDS_STABLE_RELEASE_TOKEN`
could not be read with the preparation session's credential. An active
default-branch ruleset was observed, but it contains deletion/non-fast-forward
restrictions, not required PR reviews or status checks. Neither credential
readiness nor full protection enforcement should be inferred from green CI.
The owner must verify release prerequisites before merging the promotion.

- Er zijn slechts vijf controles verdeeld over vier gedeeltelijke Microsoft-packs

## Afhankelijkheden en runtime

De ondersteunde runtime blijft Windows met PowerShell 7 of hoger (`pwsh`).
Er zijn geen runtimepakketafhankelijkheden toegevoegd; de app installeert of
actualiseert PowerShell niet automatisch. Git blijft optioneel voor
documentatiecommit/push en `Microsoft.Graph.Authentication` voor aanmelden via
Graph PowerShell. De app luistert nog uitsluitend op localhost.

Nieuwe importlimieten zijn expliciet: beleidssets staan een ZIP van 32 MiB,
1.000 items, 500 JSON-bestanden, 10 MiB per JSON, 64 MiB JSON in totaal,
64 JSON-niveaus en 16 mapniveaus toe. Een CIS build-kit-ZIP is maximaal 32 MiB;
een schema-1-regelpack-JSON maximaal 10 MiB. Een assessment selecteert 1-64
exacte regelpackversies/-profielen. Raadpleeg de
[importreferentie](../assessment-rule-packs.md) voor aanvullende archief-,
conversie- en schemagrenzen. Portal-CDP behoudt 40 seconden om gereed te worden
en een WebSocket-verbindingscontrole van vijf seconden.

## Gevolgen voor gegevens

Assessment is alleen-lezen voor de tenant. Een aangeleverde build-kit-ZIP wordt
in het geheugen verwerkt en niet bewaard; alleen gevalideerde gegenereerde
regelpacks worden in de lokale importmap opgeslagen. Assessmentrapporten gaan
uitsluitend naar de lokaal gekozen rapportmap. Klantconfiguratie, archieven en
rapporten worden niet automatisch geupload, gecommit of gepusht. Geimporteerde
packs, gelicentieerde CIS-downloads en rapporten blijven klantgegevens waarop
de toepasselijke toegangsbeperkingen en licenties van toepassing zijn.

Versiegebonden offline beleidssets bevatten hashes en ondersteund beleids-/
referentiebewijs, zonder authenticatieobjecten en herkende geheimen. Overige
configuratie blijft gevoelig. Onvolledige verzamelingen rechtvaardigen nooit
het opschonen van bestaande documentatie. Geimporteerde bronnen blijven
onafhankelijk van de aanmelding en worden nooit stilzwijgend vervangen door
live tenantgegevens.

De portalbrowser kan authenticatiemateriaal bewaren onder
`%LOCALAPPDATA%\IntuneDocsStudio\browser-profile` (Edge) of
`%LOCALAPPDATA%\IntuneDocsStudio\browser-profile-chrome` (Chrome). Behandel beide
als gevoelig, niet als applicatieback-up. Door de app beheerde toegangstokens
blijven in het procesgeheugen; deze release voegt geen tokenbestandexport toe.

## Niet-geverifieerde integraties

Er was geen gelicentieerd CIS build-kit-archief of live klanttenant beschikbaar
voor validatie. De exacte archiefindeling en conversiedekking blijven daarom
ongeverifieerd; controleer de importsamenvatting en gegenereerde regels voor
assessment. Geconverteerde CIS-labels authenticeren de bron niet en bewijzen
geen volledige benchmarkdekking, CIS-conformiteit, certificering of
apparaatcompliance. Assessmentbewijs blijft beperkt tot verzamelde configuratie
en ondersteunde regels.

Hergebruik van portaltokens blijft een niet door Microsoft ondersteund
integratiepatroon. Synthetische tests bewijzen geen compatibiliteit met iedere
beheerde Edge-/Chrome-configuratie, cloudbrowserpolicy, endpointbescherming,
Conditional Access-policy, aanmeldprocedure of actuele portalimplementatie.
Lokale registercontroles bewijzen geen effectieve toestemming om een browser
te debuggen. Graph-machtigingen, effectieve toewijzingen, Azure DevOps-/Git-
referenties en klantspecifieke update-/herstelprocedures vereisen verificatie
door de beheerder in de echte omgeving.

Bij de voorbereiding was de stabiele publicatietransactie voor deze voorgestelde
eerste release nog niet uitgevoerd. De aanwezigheid en machtigingen van
`IDS_STABLE_RELEASE_TOKEN` konden met de gebruikte referenties niet worden
gelezen. Er is een actieve regelset voor de standaardbranch waargenomen, maar
deze bevat beperkingen op verwijderen en non-fast-forward, geen verplichte
PR-reviews of statuschecks. Groene CI bewijst noch bruikbare releasereferenties
noch volledige branchbescherming. De eigenaar moet de releasevoorwaarden
controleren voordat de promotie wordt gemerged.
