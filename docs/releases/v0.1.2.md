## English

These are the reviewed notes for the owner-requested first stable publication.
The notes alone are not evidence of publication: use the GitHub Release and
its verified ZIP and manifest.

## First stable release

No stable release had been published when these notes were prepared. They
cover all user-facing changes since the original `0.1.0` source baseline,
including the changes described in the unpublished `0.1.1` notes.

The `0.1.1` attempt created pipeline version commit
`662e33c3d398d921820eaee30fbee75deb885ef7` and an immutable Actions artifact,
but final validation failed because package/runtime tests assumed the
bootstrap version. It did not create a release or tag. That commit and artifact
are preserved, not replaced or published. The existing pipeline version was
merged back into `beta` without manually editing `VERSION`; the repaired
release is the next patch, `0.1.2`. The pipeline owns its version increment.

## Good to know when updating

- After sign-in, choose **Load policies** to collect live policies. **Not now**
  opens Home without collecting; documentation and assessment require a loaded
  or imported policy source. Live loading validates Graph sign-in and requests
  reauthentication when necessary.
- The dashboard and new documentation/assessment jobs support ten languages.
  A saved choice takes precedence over a supported browser language; otherwise
  English is used. Running jobs retain their starting language, and existing
  reports are not rewritten when the interface language changes.
- Portal sign-in offers **Automatic**, **Microsoft Edge** and **Google Chrome**.
  Automatic prefers Edge and uses Chrome only if Edge is absent, never after a
  policy or connection failure. Each browser uses an isolated app profile;
  **Forget saved sessions** clears both. Browser protection is not bypassed.
- Assessment measures configuration alignment, not device compliance,
  certification or a complete benchmark. Only five checks in four partial
  Microsoft packs are bundled. Review applicability, assignments, evidence and
  collection limitations. Offline documentation supports five policy families,
  not a complete tenant backup.
- Keep documentation output, offline policy sets, imported packs, reports and
  documentation Git history separate from the application installation.
  Never back up or restore tokens or active browser-session profiles.

## Changes and user-visible effects

- Added a guided six-step assessment workflow for platform selection, pack and
  baseline import, comparison context, scope review and results. Policy alignment
  supports Windows 11, macOS, iOS/iPadOS and Android Enterprise, with evidence,
  limitations and local Markdown/JSON reports. Bundled Microsoft inventories
  remain partial.
- Added customer-supplied schema-1 rule packs and supported CIS Intune build-kit
  ZIP import. Supported Settings Catalog policies become local packs. The app
  does not download, retain or authenticate the source archive. Converted CIS
  labels do not establish provenance, complete coverage or certification.
- Added a sign-in landing page, Home policy-source status and separate
  documentation/assessment workspaces. Explicit policy loading creates one
  tenant-scoped in-memory snapshot shared by both workflows, with progress,
  collection time, family counts and retry/refresh controls. Partial collection
  retains limitations; documentation skips incomplete families and preserves
  previous files without pruning. Other selected areas are collected during
  export. CLI exports still collect directly; optional Git publishing remains
  separate from assessment.
- Added offline JSON-folder/ZIP policy-set import/export with versioned hashes,
  transactional source replacement and conservative legacy `_raw` support.
  Documentation and assessment can run without Microsoft sign-in or Graph
  requests. Offline documentation supports only five policy families;
  unavailable evidence stays unknown and incomplete-family output is preserved.
- Added a multi-item import queue, added/skipped/failed summaries, custom
  reference-policy conversion, clearer pack/profile/context/review displays,
  confirmed imported-library removal and a native Windows host-folder picker.
  Unsupported, incomplete, conflicting or secret mappings are skipped, not
  compared as generic JSON equality or labeled CIS/certified.
- Assessment tables reuse documentation setting labels/value formatting in the
  dashboard and Markdown/JSON reports. Exact typed evidence remains available;
  secret, unsupported or incomplete evidence is withheld from readable tables,
  not treated as empty. Improved large imports, structured import/report errors,
  Windows-build/platform applicability and date formatting. Unknown evidence
  remains **not assessed**, not a pass. Unassigned policies do not demonstrate
  deployment; possible conflicts do not prove overlapping effective targeting.
- Added Danish, German, English, Spanish, French, Italian, Dutch, Norwegian
  Bokmal, European Portuguese and Swedish, with a keyboard-accessible selector
  ordered by native language name. Translations and flags ship locally, without
  a translation service or CDN. Technical identifiers, typed policy values,
  customer names, provider setting labels and external benchmark wording are
  not translated. CLI exports default to `en-GB`; use `-Locale` to choose another.
- Added portal browser selection in the dashboard and CLI
  `-PortalBrowser auto|edge|chrome`. Local mandatory machine/user policy checks
  cover `RemoteDebuggingAllowed`, `DeveloperToolsAvailability`, private-browsing
  restrictions when forcing the account picker, and `UserDataDir`. CDP HTTP and
  WebSocket probes report startup/connection failures explicitly. A managed
  profile-directory override blocks launch to preserve isolation. Consult IT,
  an approved management workstation or standard Graph sign-in with admin consent
  when debugging is prohibited. The app never changes enterprise policy or
  copies an everyday browser profile.
- Aligned English and Dutch READMEs with five Dutch-interface screenshots using
  synthetic data. Added structured issue templates, an extended PR checklist,
  complete English/Dutch release notes and owner-authorized promotion guidance.
  `release:required` explicitly opts a documentation-only promotion into normal
  stable publication; unlabelled documentation-only changes do not publish.
- Fixed release validation beyond the bootstrap version: package tests use an
  explicit synthetic version, and runtime metadata matches its fixture VERSION.
  A second workflow triggered by a pipeline version push validates its original
  promotion, successful checks, notes, exact parent/trailer, VERSION-only delta,
  planned version and current local/remote heads before exiting without starting
  another release. Original promotion ownership and immutable artifacts remain
  enforced; these repairs do not bypass application or publication checks.

## Update instructions

After the stable workflow succeeds, download `IntuneDocsStudio.zip` and
`release-manifest.json` from the GitHub Release. Compare the ZIP SHA-256 with
the manifest and verify the version, `stable` channel and source-commit identity.
Do not install the unpublished `0.1.1` Actions artifact as this release.

Stop the app before replacing files. Extract into the intended application
folder following [`QUICKSTART.md`](../../QUICKSTART.md) and
[`docs/operations.md`](../operations.md). Start with `Start-IntuneDocs.cmd`;
verify `/api/health` and `/api/version`, including expected version, channel
and commit. Stable packages omit the beta title marker. Retain the previous
ZIP until the new package starts correctly.

Preserve customer output and its Git history separately from installation.
Re-check policy source, language, report/output paths, approved portal browser
and tenant before generating output. Do not copy, back up or restore tokens
or active browser profiles; sign in again if needed.

## Dependencies and runtime

Windows with PowerShell 7 or later (`pwsh`) remains required. No runtime package
dependencies were added; PowerShell is never automatically installed or updated.
Git is optional for documentation commit/push; `Microsoft.Graph.Authentication`
is optional for Graph PowerShell sign-in. The app binds only to localhost.

Policy-set limits: 32 MiB ZIP, 1,000 entries, 500 JSON files, 10 MiB per JSON,
64 MiB total JSON, 64 JSON levels and 16 folder levels. A CIS build-kit ZIP is
limited to 32 MiB; schema-1 pack JSON to 10 MiB. An assessment selects 1-64 exact
pack versions/profiles. See the [import reference](../assessment-rule-packs.md)
for additional archive/conversion/schema bounds. CDP startup has a 40-second
readiness window and a five-second WebSocket probe.

## Data implications

Assessment is read-only against the tenant. Build-kit archives are processed
in memory and not retained; only validated generated packs are stored locally.
Reports go only to the operator-selected local folder. Customer configuration,
archives and reports are not automatically uploaded, committed or pushed.
Imported packs, licensed CIS downloads and reports remain customer-owned and
subject to applicable licensing and access controls.

Versioned offline policy sets contain hashes and supported policy/reference
evidence, excluding authentication objects and recognized secrets. Remaining
configuration is sensitive. Incomplete collections never justify pruning old
documentation. Imported sources remain independent of sign-in and are never
silently replaced with live tenant data.

Browser authentication material may persist in
`%LOCALAPPDATA%\IntuneDocsStudio\browser-profile` for Edge and
`%LOCALAPPDATA%\IntuneDocsStudio\browser-profile-chrome` for Chrome. Both are
sensitive, not application backup data. App-managed access tokens stay in
process memory; token-file export is not added.

## Unverified integrations

No live customer tenant or licensed CIS build-kit archive was available.
Archive layout/conversion coverage, real Graph permissions, effective
assignments, Azure DevOps/Git credentials and customer-specific update/restore
procedures require operator verification. Inspect import summaries and generated
rules. Synthetic fixtures do not establish complete benchmark coverage,
conformance, certification or device compliance.

Portal-token reuse remains an unsupported Microsoft integration pattern.
Not every managed browser/cloud policy, endpoint protection product, Conditional
Access policy, sign-in flow or portal implementation has been verified.
Local registry checks do not prove effective permission to debug a browser.

The earlier token/configuration blocker was resolved far enough to push the
`0.1.1` version commit and upload its artifact, but those runs did not publish.
At note preparation, successful end-to-end publication/back-sync still required
verification. An observed default-branch ruleset restricts deletion and
non-fast-forward updates; it does not establish required reviews/status checks.
Do not infer full branch enforcement or tenant compatibility from green CI.

## Afhankelijkheden en runtime

Windows met PowerShell 7 of hoger (`pwsh`) blijft vereist. Er zijn geen
runtimepakketafhankelijkheden toegevoegd; PowerShell wordt nooit automatisch
geinstalleerd of bijgewerkt. Git is optioneel voor documentatiecommit/push;
`Microsoft.Graph.Authentication` voor Graph PowerShell-aanmelding. De app
luistert uitsluitend op localhost.

Beleidssetlimieten: ZIP 32 MiB, 1.000 items, 500 JSON-bestanden, 10 MiB per JSON,
64 MiB JSON totaal, 64 JSON-niveaus en 16 mapniveaus. Een CIS build-kit-ZIP
is maximaal 32 MiB; schema-1-pack-JSON maximaal 10 MiB. Een assessment kiest
1-64 exacte packversies/-profielen. Zie de [importreferentie](../assessment-rule-packs.md)
voor aanvullende archief-/conversie-/schemagrenzen. CDP heeft 40 seconden om
gereed te worden en een WebSocket-controle van vijf seconden.

## Gevolgen voor gegevens

Assessment is alleen-lezen voor de tenant. Build-kit-archieven worden in het
geheugen verwerkt en niet bewaard; alleen gevalideerde gegenereerde packs
worden lokaal opgeslagen. Rapporten gaan uitsluitend naar de lokaal gekozen
map. Klantconfiguratie, archieven en rapporten worden niet automatisch geupload,
gecommit of gepusht. Geimporteerde packs, gelicentieerde CIS-downloads en
rapporten blijven klantgegevens met toepasselijke licenties en toegangsbeperkingen.

Versiegebonden offline beleidssets bevatten hashes en ondersteund beleids-/
referentiebewijs, zonder authenticatieobjecten en herkende geheimen.
Overige configuratie blijft gevoelig. Onvolledig verzamelen rechtvaardigt
nooit opschonen van oude documentatie. Geimporteerde bronnen blijven
onafhankelijk van aanmelden en worden nooit stilzwijgend vervangen door live
tenantgegevens.

Browserauthenticatiemateriaal kan bewaard blijven in
`%LOCALAPPDATA%\IntuneDocsStudio\browser-profile` voor Edge en
`%LOCALAPPDATA%\IntuneDocsStudio\browser-profile-chrome` voor Chrome. Beide
zijn gevoelig, geen applicatieback-up. App-beheerde toegangstokens blijven
in procesgeheugen; tokenbestandexport is niet toegevoegd.

## Niet-geverifieerde integraties

Er was geen live klanttenant of gelicentieerd CIS build-kit-archief beschikbaar.
Archiefindeling/conversiedekking, echte Graph-machtigingen, effectieve
toewijzingen, Azure DevOps-/Git-referenties en klantspecifieke update-/
herstelprocedures vereisen verificatie door de beheerder. Controleer
importsamenvattingen en gegenereerde regels. Synthetische fixtures bewijzen
geen volledige benchmarkdekking, conformiteit, certificering of apparaatcompliance.

Hergebruik van portaltokens blijft een niet door Microsoft ondersteund
integratiepatroon. Niet elke beheerde browser-/cloudpolicy, endpointbescherming,
Conditional Access-policy, aanmeldprocedure of portalimplementatie is
geverifieerd. Lokale registercontroles bewijzen geen effectieve toestemming
om een browser te debuggen.

De eerdere token-/configuratieblokkade is voldoende verholpen om de versiecommit
voor `0.1.1` te pushen en het artifact te uploaden, maar die runs publiceerden
niets. Bij het voorbereiden vereisten geslaagde volledige publicatie en
terugsynchronisatie nog verificatie. Een waargenomen standaardbranchregelset
beperkt verwijderen en non-fast-forward; die bewijst geen verplichte reviews/
statuschecks. Leid volledige branchbescherming of tenantcompatibiliteit niet
af uit groene CI.
